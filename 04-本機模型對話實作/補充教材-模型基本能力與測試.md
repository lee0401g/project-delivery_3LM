# 補充教材-模型基本能力與測試

本文件供需要了解文字型大型語言模型基本功能，或比較不同模型實際表現的學生及教師使用

模型大小可以作為理解硬體需求與能力傾向的初步線索，但不能直接當成能力等級；模型大小可以量測，模型能力則需要透過具體任務實測

## 文字型模型的基本功能

| 基本功能 | 白話說明 | 常見例子 |
| --- | --- | --- |
| 撰寫 | 根據要求產生文字 | 寫信、草擬文案、擬定大綱 |
| 改寫與翻譯 | 改變文字的語言或表達方式 | 翻譯、潤稿、改成白話文 |
| 摘要 | 把大量內容整理成重點 | 文章摘要、會議重點 |
| 擷取與分類 | 找出指定資訊並依規則整理 | 擷取日期與金額、分類客訴 |
| 問答與解說 | 依據已學知識或提供的資料解答 | 解釋名詞、回答文件問題 |
| 分析與規劃 | 比較資訊、推導步驟並提出方案 | 比較方案、拆解任務、協助寫程式 |

這是用途分類，不代表每個模型都能可靠完成所有項目；問答是否正確、分析是否合理及多次回答是否穩定，都需要另外評估

> 能上網、讀取圖片、處理聲音或操作軟體，還需要相應的模型能力或外接工具，不能只從模型大小判定

## 模型大小與參數量

模型大小通常以參數量表示，參數可粗略理解為模型在訓練中學到、用來處理資訊的內部數值，不是資料庫筆數，也不是模型可以記住多少字

常見標示中的 `B` 是 billion（十億）

| 標示 | 代表的參數量 |
| --- | ---: |
| 1B | 約 10 億 |
| 8B | 約 80 億 |
| 70B | 約 700 億 |

模型的公開參數量可以作為規模規格，但「小型」「中型」「大型」沒有普遍統一的分界，會隨模型系列、架構與比較對象而改變

> 若使用小、中、大等稱呼，應說明這是該文件採用的分類；直接標示 `3B` 或 `8B` 會更明確

### 混合專家模型

Mixture of Experts（MoE，混合專家模型）需要區分「總參數」與「每次處理一個 token 時啟用的參數」

例如某個模型可能具有約 30B 總參數，但每次只啟用約 3B；比較 MoE 模型時，應確認資料指的是哪一種參數量

## 大小與能力的關係

以下是方便理解的概念框架，不是正式分級標準，也沒有固定的參數切點

| 大小定位 | 給一般使用者的直覺說明 | 適合優先測試的工作 |
| --- | --- | --- |
| 較小模型 | 處理明確、範圍有限的文字工作 | 固定分類、欄位擷取、簡單改寫 |
| 中等模型 | 處理需要理解上下文的綜合工作 | 摘要、文件問答、一般內容草擬 |
| 較大模型 | 處理條件較多、需要多步分析的工作 | 複雜比較、規劃、較困難的程式問題 |

模型變大通常不是多出全新功能，而是相同功能能處理的複雜度、細節與穩定性可能不同；訓練資料、訓練方式、模型架構、量化與提示詞也會影響表現，因此不能只看參數量判定強弱

面向一般使用者介紹模型時，可以分開記錄：

| 標示 | 判定依據 |
| --- | --- |
| 規模規格 | 參數量、架構、模型檔案與量化方式 |
| 輸入能力 | 是否支援文字、圖片、聲音或其他資料 |
| 功能規格 | 官方說明支援哪些任務或工具 |
| 實測表現 | 指定任務、難度、測試條件、正確率與穩定性 |

## 基本能力測試方式

以下六題用於比較模型的文字處理能力，不需要連接網路

- 每題使用新對話，避免前一題內容影響結果
- 不同模型使用完全相同的提示詞與設定
- 每題重複測試三次，觀察結果是否穩定
- 保留模型完整標籤、量化版本、上下文設定與測試日期
- 這是基本能力初測，不是正式認證或完整能力評估

### 1 撰寫

測試模型能否依照要求產生內容

```markdown
請根據以下資訊，撰寫一封通知客戶的電子郵件：

- 客戶稱呼：林小姐
- 原定交貨日：10 月 12 日
- 新交貨日：10 月 15 日
- 延遲原因：出貨前檢查發現包裝破損，需要重新包裝
- 商品本身沒有發現損壞
- 若新日期不方便，請客戶回信討論安排

要求：
1. 提供郵件主旨與內文。
2. 使用繁體中文，語氣專業、誠懇。
3. 內文不超過 180 字。
4. 清楚表達歉意與新交貨日期。
5. 不得自行承諾折扣、賠償或其他未提供的事項。
```

評分檢查：

- [ ] 有主旨、稱呼與完整內文
- [ ] 日期與延遲原因正確
- [ ] 有歉意，也有請客戶回信的安排
- [ ] 符合字數、語言要求，且沒有自行增加承諾

### 2 改寫與翻譯

測試模型能否改變表達並保留原意

```markdown
請處理以下原文：

「申請人應於收到通知翌日起七日內補齊文件；逾期未補齊者，
本次申請不予受理。因不可抗力因素無法如期補件者，
得於期限屆滿前提出延期申請，是否核准由承辦單位審認。」

請完成兩項工作：
A. 改寫成一般民眾容易理解的繁體中文。
B. 翻譯成英文。

要求：
1. 保留起算時間、期限、逾期後果與延期條件。
2. 不得把「可以申請延期」寫成「一定可以延期」。
3. 不得自行增加原文沒有的規定。
```

評分檢查：

- [ ] 中文改寫更容易理解
- [ ] 中、英文都保留收到通知的隔天起算七日
- [ ] 中、英文都保留逾期不受理及期限前提出延期申請
- [ ] 保留不可抗力條件與核准的不確定性，沒有增加規定

### 3 摘要

測試模型能否找出重點並保留決定與不確定性

```markdown
請將以下會議紀錄整理成恰好三點摘要，總長不超過 150 字。
摘要應涵蓋目前進度、已決定事項，以及待辦工作。
不得把提議或尚未確認的事情寫成已決定。

會議紀錄：
新版網站原定 6 月 10 日上線。目前付款功能已完成，
但退款功能仍有兩項錯誤。行銷部提議照原日期上線，
先暫停退款功能；客服部認為這會增加客訴。
會議最後決定延至 6 月 17 日上線。
工程部由怡君負責，6 月 12 日前完成修正，
測試部於 6 月 14 日前完成驗證。
若驗證未通過，是否再次延期須另行決定。
行銷部將調整公告，但公告日期尚未確認。
```

評分檢查：

- [ ] 恰好三點，總長符合限制
- [ ] 指出付款已完成、退款仍有兩項錯誤
- [ ] 正確列出新上線日、修正與驗證期限，以及相關負責人或單位
- [ ] 沒有把行銷提議當成決議，也沒有把再次延期或公告日期寫成已確定

### 4 擷取與分類

測試模型能否依規則整理資料

```markdown
請將以下客戶訊息整理成 JSON 陣列，只輸出 JSON，不要附加解說。

每筆資料必須包含：
id、category、order_id、amount

分類規則：
- 提及退款或退貨，一律分類為「退款」。
- 其餘提及尚未收到貨品，分類為「物流」。
- 其餘詢問使用方式，分類為「使用諮詢」。
- 不符合上述條件，分類為「其他」。

資料規則：
- order_id 使用字串。
- amount 使用數字。
- 沒有明確提供的訂單編號或金額，一律填 null。
- 不得自行推測。

客戶訊息：
A.「訂單 A102 還沒收到，已經等五天了。」
B.「我要退掉訂單 B205，購買金額是 1,280 元。」
C.「請問這台設備怎麼恢復原廠設定？」
D.「訂單 D410 還沒送到，我不想等了，請退款。」
```

評分檢查：

- [ ] 是有效的 JSON，包含四筆資料與全部指定欄位
- [ ] A 為物流、B 為退款、C 為使用諮詢、D 為退款
- [ ] 訂單編號正確，C 的 `order_id` 為 `null`
- [ ] 只有 B 的金額為 `1280`，其他金額皆為 `null`

### 5 問答與解說

測試模型能否根據資料回答並承認資訊不足

```markdown
請只根據以下規則回答問題，不要使用外部知識。
資料不足時，請明確說明無法判定，以及缺少什麼資訊。

規則：
- 標準會員每月可免費預約會議室 2 小時。
- 進階會員每月可免費預約 5 小時。
- 超過免費額度的部分，每小時收費 300 元。
- 未使用的免費額度不能轉到下個月。
- 預約開始前至少 24 小時取消，不扣額度、不收費。
- 不足 24 小時才取消，依原預約時數計入使用量。

問題：
1. 標準會員本月已使用 1 小時，再預約 2 小時，
   這次預約需要付多少錢？請說明計算方式。
2. 進階會員上個月剩下 3 小時沒用，本月有多少免費額度？
3. 小明在預約開始前 12 小時取消了 2 小時的預約，
   他需要付多少錢？
```

評分檢查：

- [ ] 第 1 題回答 300 元
- [ ] 第 1 題正確說明剩餘免費額度 1 小時，另 1 小時收費
- [ ] 第 2 題回答 5 小時，不能累加上月餘額
- [ ] 第 3 題指出會計入 2 小時使用量，但缺少會員等級與當月額度使用情形，不能確定費用

### 6 分析與規劃

測試模型能否同時處理多項限制

```markdown
請根據以下條件，安排一個最早完成的專案時程。

工作：
A：需求確認，2 天，必須最先完成。
B：畫面設計，3 天，必須在 A 完成後開始。
C：資料整理，2 天，必須在 A 完成後開始。
D：系統整合，2 天，必須在 B 與 C 都完成後開始。
E：驗收，1 天，必須在 D 完成後開始。

資源限制：
- 只有小林與小陳兩位人員。
- A、B、D、E 只能由小林執行。
- C 只能由小陳執行。
- 每個人同一天只能執行一項工作。
- 工作不能中斷；不考慮假日。
- 每項工作都占用完整工作日，完成後隔天才能開始後續工作。

請回答：
1. 以表格列出每項工作的負責人、開始日與結束日，
   從第 1 天起算。
2. 最早可以在第幾天結束時完成全部工作？
3. 說明為什麼不能更早完成。
4. 如果 C 改成需要 4 天，最早完成日會如何改變？
```

評分檢查：

- [ ] 原安排為 A：第 1～2 天、B：第 3～5 天、C：第 3～4 天、D：第 6～7 天、E：第 8 天
- [ ] 負責人正確，沒有違反工作相依性或人力限制
- [ ] 回答第 8 天完成，並指出 A → B → D → E 的必要順序共需 8 天
- [ ] C 改成 4 天後，延至第 6 天結束；D 為第 7～8 天、E 為第 9 天
