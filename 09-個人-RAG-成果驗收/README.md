# 單元 09 個人 RAG 成果驗收

## 1 教學目標

- 學生能確認本機模型與知識庫在重新啟動後仍可使用
- 學生能完成單一文件整理與跨文件比較
- 學生能分析文件證據、支持程度與資料缺口
- 學生能根據知識庫整理主題並提出規劃
- 學生能利用原始文件判斷回答與引用是否可信
- 學生能記錄目前成果與仍待改善之處

## 2 必要觀念

### 驗收分成系統與回答兩部分

| 驗收部分 | 檢查重點 |
| --- | --- |
| 系統驗收 | 服務能啟動、網頁能開啟、模型能回答、知識庫仍存在 |
| 回答驗收 | 回答符合問題、重要主張有來源、引用支持主張、資料不足時不自行補足 |

系統能正常啟動不代表回答一定正確，回答附有來源也不代表來源一定支持內容

### 原始文件是查核依據

驗收時至少抽查三項重要主張，依序確認

1. 回答中的主張是什麼
2. 回答標示哪一份來源
3. 原始文件是否包含相關內容
4. 原文是否直接支持整項主張
5. 回答是否遺漏前提、例外或不同說法

查核結果分為

- 直接支持：原文足以支持整項主張
- 部分支持：原文只支持部分內容或回答遺漏限制
- 不支持：來源與主張無關或無法推出該結論
- 資料不足：目前文件沒有足夠內容可供判斷

### 整理與推論應分開呈現

文件中的明確內容屬於資料整理，根據資料提出的評論、判斷或規劃則可能包含推論

要求模型分開標示「文件內容」與「分析建議」，可避免讀者將推論誤認為原文結論

### 找出限制也是驗收成果

小型本機模型可能在長文件、複雜表格、多份文件整合或繁體中文表達上出現不足

驗收不是要求每次回答都完美，而是確認使用者能發現問題、查核來源並選擇重新提問、補充資料或調整文件

## 3 要點

- 先確認服務、模型與知識庫可用，再進行回答品質驗收
- 四項任務均使用學生自己的知識庫與實際主題
- 每項重要結論都要求來源，且至少抽查三項主張
- 比較不同文件時保留相同、相反與不足之處
- 規劃內容需要區分文件依據與分析建議
- 資料不足測試應使用確定未收錄於知識庫的內容
- 外網中斷測試只在模型與文件都已下載完成後執行
- 第 08 單元的完整移除功能應留到本單元結束後再使用

## 4 實作

### 步驟一 準備驗收資料

1. 選擇一個已在第 05 至第 07 單元使用的個人知識庫
2. 確認知識庫包含至少兩份可正常擷取文字的文件
3. 確認本機仍保有各文件的原始檔
4. 確認檔名可辨認主題與版本
5. 準備一個文件內已有答案的問題
6. 準備一個文件內沒有答案的問題

### 步驟二 進行系統驗收

1. 啟動 Docker Desktop 並等待 Engine running
2. 開啟 `03_service-control.cmd`
3. 選擇 `1 Start Ollama and Open WebUI`
4. 返回選單並選擇 `2 View service status`
5. 確認 Ollama 與 Open WebUI 狀態都是 Up
6. 開啟 [http://localhost:3000](http://localhost:3000)
7. 登入自己的本機帳號
8. 建立新對話並選擇 `phi4-mini:3.8b-q4_K_M`
9. 輸入一個簡短問題並確認模型能正常回答
10. 開啟 "工作區（Workspace）" > "知識庫（Knowledge）"，確認個人知識庫與文件仍然存在

### 步驟三 設定共同回答原則

四項驗收任務都先輸入下列內容

```text
只根據目前選擇的文件或知識庫回答
每項重要結論都要標示來源檔名
請分開標示文件明確記載的內容與你的分析建議
若資料不足，請直接說明缺少哪些資料
若文件說法不同，請分別保留，不要自行合併成單一結論
不要利用知識庫以外的資訊補足答案
```

### 步驟四 驗收任務一 單一文件整理

選擇一份內容較短且自己熟悉的文件，建立新對話並只連結該文件

```text
請整理這份文件

1 列出主要內容架構
2 摘要各部分重點
3 指出文件提出的主要結論
4 評論內容的優點、不足與未說明之處

每項內容都要標示來源
評論與文件原文必須分開呈現
```

查核回答是否涵蓋文件主要部分，並確認評論沒有被寫成文件原有結論

### 步驟五 驗收任務二 跨文件比較

建立新對話並連結整個知識庫

```text
比較知識庫中各文件對「［主題］」的說法

請分成
1 共同觀點
2 相互支持的內容
3 相反或不一致的內容
4 各文件特有的內容
5 目前無法判斷之處

每項內容都要標示來源檔名
```

將 `［主題］` 改成至少兩份文件都有提及的實際主題

確認回答沒有把不同文件的觀點錯接成同一份文件的內容

### 步驟六 驗收任務三 證據與資料缺口

建立新對話並連結整個知識庫

```text
針對「［問題或主張］」分析目前知識庫

請列出
1 支持的證據
2 反對或限制條件
3 每項證據的來源
4 支持程度為直接支持、部分支持、不支持或資料不足
5 尚缺少哪些資料

不要在缺少證據時自行做出肯定結論
```

先使用文件內已有答案的問題，再使用文件內沒有答案的問題

確認第二次回答能明確指出資料不足，而不是利用一般常識自行回答

### 步驟七 驗收任務四 主題整理與規劃

建立新對話並連結整個知識庫

```text
根據知識庫整理「［主題或目標］」並提出一份執行規劃

請分成
1 文件提供的已知條件
2 建議執行順序
3 每個步驟的文件依據
4 需要由使用者決定的事項
5 執行前仍需補充的資料

文件沒有直接提供的內容請標示為分析建議
每項文件依據都要標示來源
```

確認規劃有利用文件內容，也有清楚標示模型自行整理或推論的部分

### 步驟八 抽查來源

從四項任務中選擇至少三項重要主張，填寫下表

| 任務 | 回答主張 | 來源檔名 | 原文位置或片段 | 查核結果 | 說明 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  | 直接支持／部分支持／不支持／資料不足 |  |
|  |  |  |  | 直接支持／部分支持／不支持／資料不足 |  |
|  |  |  |  | 直接支持／部分支持／不支持／資料不足 |  |

若其中一項為部分支持或不支持，修改問題後再提問一次，記錄回答是否改善

### 步驟九 測試外網中斷時使用

> 執行前確認 `phi4-mini:3.8b-q4_K_M`、`embeddinggemma:300m-qat-q4_0` 與知識庫文件都已完成下載及處理

1. 暫時中斷測試電腦的外網連線
2. 保持 Docker Desktop、Ollama 與 Open WebUI 執行
3. 開啟 [http://localhost:3000](http://localhost:3000)
4. 建立新對話並選擇 `phi4-mini:3.8b-q4_K_M`
5. 連結個人知識庫
6. 重複一個已通過來源查核的問題
7. 確認模型能回答且來源仍可開啟
8. 測試完成後依上課環境恢復網路連線

外網中斷後仍可使用代表本次操作所需模型與資料已保存在本機，不代表所有 Open WebUI 擴充功能都能離線使用

## 5 成功檢查

- Ollama 與 Open WebUI 可正常啟動
- `phi4-mini:3.8b-q4_K_M` 可進行繁體中文對話
- 個人知識庫至少包含兩份可檢索文件
- 四項驗收任務均已留下對話紀錄
- 至少三項重要主張已完成原文查核
- 沒有將不支持的引用判定為通過
- 資料不足測試能指出缺少的資料
- 文件內容與分析建議能分開辨認
- 外網中斷時仍可進行本機模型與知識庫問答
- 至少一項目前限制與改善方式已留下紀錄

## 6 常見問題與排除

### 服務無法啟動

返回 [單元 03 啟動 Ollama 與 Open WebUI](../03-啟動-Ollama-與-Open-WebUI/README.md) 檢視服務狀態與錯誤紀錄

### 模型無法回答或速度過慢

返回 [單元 04 本機模型對話實作](../04-本機模型對話實作/README.md) 確認模型是否已下載完成，並縮短單次問題與回答長度

### 知識庫或文件找不到

返回 [單元 05 建立個人知識庫](../05-建立個人知識庫/README.md) 檢查知識庫、文件處理狀態與索引模型設定

### 回答沒有來源或來源不支持主張

返回 [單元 06 文件問答與引用查核](../06-文件問答與引用查核/README.md) 縮小問題範圍、指定文件並重新查核原文

### 回答仍引用過期文件

返回 [單元 07 資料更新與知識庫維護](../07-資料更新與知識庫維護/README.md) 確認新版已完成處理並移除舊版

### 備份或還原尚未驗證

返回 [單元 08 備份、還原、停止與移除](../08-備份還原停止與移除/README.md) 完成備份資料夾與還原結果檢查

### 中斷外網後無法使用知識庫

恢復網路後確認對話模型與索引模型都已下載完成，文件也已完成處理，再重新進行中斷外網測試

## 7 單元成果

學生完成一套可在本機使用的個人 RAG，能利用自己的文件進行整理、比較、證據分析與規劃，並能查核來源、辨認資料不足及記錄目前限制
