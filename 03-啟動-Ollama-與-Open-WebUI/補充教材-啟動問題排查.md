# 補充教材：啟動問題排查

## 1 先確認問題發生在哪裡

先記錄腳本畫面版本、執行位置、選單選項與時間，再取得對應 TXT
確認執行的是目前教材資料夾裡的 CMD；更新後關閉先前視窗再重新開啟

| 情況 | 檢查方向 |
| --- | --- |
| Docker 指令不存在 | 安裝狀態、安裝位置與重新開啟終端後的環境 |
| Docker Engine 無法連線 | Docker Desktop 是否啟動、是否顯示 Engine running，以及 Docker 本身的錯誤 |
| Compose 啟動失敗 | 下載失敗、磁碟空間、設定檔或連接埠占用，以紀錄原文為準 |
| 容器啟動但網頁探測失敗 | 查看容器狀態、HTTP 探測原因，並確認手動網址是否可用 |
| 就緒後瀏覽器未開啟 | 查看瀏覽器啟動例外及 Windows 的 HTTP 預設程式關聯 |

## 2 腳本判定與等待規則

腳本啟動服務後，會檢查 Open WebUI 容器狀態及本機網頁
條件成立後才會立即開啟瀏覽器

| 項目 | 實際行為 |
| --- | --- |
| 探測地址 | `http://127.0.0.1:3000/`，配合 Compose 綁定的本機 IPv4 地址 |
| 瀏覽器網址 | `http://localhost:3000/`，交由 Windows 的 HTTP 預設程式開啟 |
| 單次探測 | 最多 5 秒，剩餘總時間不足時縮短 |
| 狀態更新 | 約每 5 秒，Docker 查詢較慢時可能延長 |
| 正常初始化 | Compose 啟動成功後最多約 180 秒，不含首次下載時間 |
| 疑似故障 | 持續約 15 秒後提前停止，輸出 TXT |
| 明確故障 | 立即停止該次檢查並輸出 TXT |

> 上限由實際經過時間判定，並非每次都要等滿

> 錯誤發生後收集 Docker 診斷資訊可能另外花費少量時間

| 狀態或回應 | 判讀與處理 |
| --- | --- |
| `running / healthy / 200` | 符合自動開啟條件 |
| `starting` | 容器仍在初始化，可繼續觀察 |
| `N/A (Timeout)` | 未在單次上限內取得 HTTP 回應，不能單憑此結果判定網站故障 |
| `N/A (ConnectFailure)` | 連線失敗，查看 TXT 的完整例外 |
| `N/A (NotChecked)` | 尚未探測，例如容器沒有執行 |
| `502 / 503 / 504` | 可能暫時不可用，結合 health 判定；若已 healthy 仍失敗則進入短暫觀察 |
| `unhealthy / restarting` | 疑似故障，持續約 15 秒後停止 |
| HTTP 3xx、4xx 或其他 5xx | 疑似重新導向、權限、網址或服務錯誤，短暫觀察後停止 |
| 容器不存在、exited、dead、paused、removing | 明確故障，直接停止 |
| 執行中的容器沒有 health check | 檢查映像與 Compose 設定 |

> `N/A` 是腳本用來表示未取得回應的文字，不是伺服器回傳的狀態碼

> 容器健康檢查通過，也不代表 Windows 端的網頁探測必定成功

> 如果手動網頁可用，應優先比較探測路徑與例外原因

## 3 TXT 錯誤紀錄

預設位置：CMD 同資料夾下的 `logs\error-時間戳記-識別碼.txt`
若無法寫入，改存 `%TEMP%\LocalAI-ServiceControl\`，以畫面 `Error report:` 後的完整路徑為準
每次錯誤建立獨立檔案；兩處都寫入失敗時，控制視窗會顯示儲存失敗

紀錄包含：

- 腳本版本、路徑、時間、探測與瀏覽器地址
- 完整錯誤及 HTTP 探測原因
- 該次操作累積的探測歷程或 Compose 輸出
- 可取得的容器狀態及最近 30 行 Open WebUI 日誌

瀏覽器啟動失敗也會記錄，但該分支不額外收集容器日誌

> 分享紀錄前，先遮蔽本機個人路徑、帳號、使用者識別資訊及其他敏感內容

## 4 常用查詢

以下指令須在包含 `03_compose.yaml` 的資料夾執行

```console
docker compose -f 03_compose.yaml ps --all
docker compose -f 03_compose.yaml logs --tail 100 open-webui
docker compose -f 03_compose.yaml logs --tail 100 ollama
```

若確認 Ollama 停止或需重新啟動，可在等待進行中的工作完成後執行：

```console
docker compose -f 03_compose.yaml restart ollama
```

若 3000 連接埠被占用，先查明占用來源，不要任意終止程式

> 修改 Compose 的本機連接埠時，也必須同步修改腳本探測地址、瀏覽器地址與教材中的網址

## 5 資料保留與進一步處理

選項 3 使用 `compose stop`，保留帳號、對話與模型資料

> 設定 `restart: unless-stopped` 可能讓未手動停止的容器在 Docker 恢復後自行啟動；選項 1 仍可重新確認狀態並開啟網頁

忘記密碼、資料庫錯誤或重複重啟時，先保存日誌並確認備份

> 例如 `no such table: config` 表示資料庫預期的表不存在，需檢查初始化或資料庫遷移紀錄，不能僅憑此訊息決定刪除資料

`docker volume rm local-ai_open-webui-data` 會永久刪除 Open WebUI 帳號、對話、設定與上傳資料

> 由於非一般啟動問題的排除步驟，不應讓學員直接執行。有重建需求時，應由教師確認資料是否需要保留、完成備份並另訂處理步驟
